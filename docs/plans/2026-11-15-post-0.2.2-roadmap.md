## 0. Резюме

Продукт функционально готов: 17 CLI-команд, 11 MCP-инструментов, 3 скилла, краулер, отчёты,
планировщики, подписанные обновления на трёх ОС. Следующий рост — не «ещё один провайдер», а
**закрытие дыр, завершение десктопного workflow и weekly-loop, которого нет у бесплатных
инструментов**.

Главные выводы аудита:

1. **Безопасность оболочки.** Несколько путей обходят уже существующие защиты: сырой `stderr`
   движка с токенами, `open_path` открывает неканонический путь, `updater:default` доступен
   webview, workspace-конфиг может подсунуть UNC-путь. Это чинится точечно и не требует
   переписывания.
2. **Честность данных.** GSC отдаёт `total=len(rows)` при `truncated=true`, `data_age_days`
   игнорирует лаг GSC, Metrika не умеет paging. Это ломает главный принцип продукта —
   «не врать о покрытии».
3. **Контракты.** MCP write-инструменты не используют confirm-token, exit code 5 недостижим,
   ledger не читает `--config`, `schedule install` может удалить чужие строки crontab.
4. **Десктоп.** Нет crawl-экрана, истории/диффа отчётов, онбординга, выбора окна дат; есть
   реальные баги (skip-link, потеря правок при сохранении, `configExists` не читается).
5. **Продукт.** Три ставки с лучшим соотношением ценность/усилие: **attributed change digest +
   alarms**, **client report packs**, **log ingest** (парсер логов уже написан, но не выведен).

Рекомендуемая последовательность:

| Релиз | Содержание | Оценка |
|---|---|---|
| `0.2.3` / `0.5.3` | P0: безопасность, честность данных, контракты, баги десктопа, CI-гейты | 2–3 недели |
| `0.3.0` | десктопный workflow: онбординг, crawl, история/дифф отчётов, настройки, экспорт | 3–4 недели |
| `0.4.0` | weekly loop: digest+alarms, decay queue, log ingest, report packs, internal links | 4–6 недель |
| `0.5.0+` | coverage truth table, multi-site, hreflang/CWV-разрезы, docs-скриншоты | 6–10 недель |

## 1. Приоритеты и определения

| Приоритет | Что входит | Правило |
|---|---|---|
| **P0** | утечка секретов, обход write-gate, потеря данных, ложь о покрытии, падение/зависание | Блокирует релиз; фиксится до новых фич |
| **P1** | workflow, без которого продукт не используют еженедельно | Следующий минор |
| **P2** | дифференциаторы и «вау» для агентского/агентского-клиентского сценария | После P1 |
| **P3** | масштаб, портфель, косметика, документация | По мере спроса |

Effort: **S** ≤ 1 день, **M** 2–4 дня, **L** 1–2 недели (на одного исполнителя; рой делит внутри).

## 6. Постоянный трек качества (параллельно всем фазам)

- **Контракты:** engine ↔ desktop CLI (`contracts/cli-v1`), MCP registry ↔ schemas,
  `latest.json` schema. Любой дрейф — красный CI.
- **Матрица ОС:** engine — Linux/Windows/macOS; desktop — Linux/Windows/macOS arm64 + x64.
- **Покрытие:** floor для engine и desktop; interaction-тесты для update/settings.
- **Безопасность:** `pip-audit`, `npm audit`, `cargo-audit`, dependabot; пин actions/toolchain.
- **Релизы:** тесты release-скриптов, SHA256SUMS + portable `.sha256`, release-notes gate,
  immutable tags, ручной smoke на трёх ОС.
- **Документация:** release notes + docs portal (en/ru/zh) в том же PR; скриншоты — отдельным
  проходом после стабилизации UI.

---

## 7. Что не строим

- **SERP rank tracking** — требует скрейпинга или платного API, ломается еженедельно.
- **Backlink index / domain authority** — нужен краул всего веба; бесплатная версия будет
  устаревшей и нечестной.
- **AI content writing** — коммодитизировано агентами, которые уже потребляют MCP; добавляет
  токен-косты и не даёт доказательств.
- **Cloud accounts / team seats / sync** — противоречит local-first; portable bundle решает
  передачу без биллинга, GDPR и поддержки.

Правила для каждого WP:

1. Один PR = одна область (`cli`, `mcp`, `providers`, `crawl`, `report`, `store`, `desktop`,
   `docs`, `infra`, `tests`).
2. Тест на баг/границу/праву — в том же PR; для security — тест, который падает без фикса.
3. Не ослаблять `limitations[]`, truncation и write-gating ради зелёного теста.
4. Обновлять release notes и docs portal в том же PR.
5. DoD: `ruff` + `mypy` + `pytest`; `typecheck` + `test` + `build` + `cargo clippy/test`;
   docs `npm test` + lint + build; зелёный CI на трёх ОС.
