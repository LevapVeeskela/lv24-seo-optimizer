# 0.15.3 - Crawl TLS facts, CJK word counts and the weekly email restyle

Status: **released** (2026-11-19) on PyPI, npm and the MCP Registry. Desktop `0.9.8` bundles
engine `0.15.2`.

Patch release: two crawl correctness fixes and the LV24 visual language for the weekly report
email.

## Fixed

### TLS facts survive the response body

The fetcher captured TLS facts after reading the body. httpcore clears the SSL object's peer
certificate once the stream is closed, so the `tls-certificate` rule and `FetchResult.tls` could
lose protocol, cipher and certificate details on ordinary `200` responses.

TLS facts are now read before the body is consumed. The rule keeps reporting the same fields and
limitations; it simply sees the connection that actually served the page.

### CJK ideographs count as words

`word_count` used `len(text.split())`. Chinese and Japanese pages rarely use spaces, so a
substantial page such as `/games?lang=zh` looked like a three-word page and produced false
thin-content and soft-404 findings.

Every CJK ideograph (`U+4E00`-`U+9FFF`) now counts as one word; Latin and Cyrillic tokens still
count once, so existing English and Russian thresholds are unchanged. The stored text cap still
uses the full body, not the truncated copy.

## Changed

### Weekly report email visual language

`render_html` now matches the LV24 email look:

* dark gradient header and footer with a solid dark fallback for clients that drop gradients;
* one orange accent (`#FB6E4A`) for the logo, section bars, KPI labels and links in the footer;
* KPI cards with a light card surface, large value and a status pill for significant changes;
* section headings with an orange accent bar;
* rounded data tables with a light header row and severity pills;
* opportunity, digest and Core Web Vitals rows as rounded cards with an orange edge.

The change is presentation-only. `render_text`, `render_email_text`, `render_subject`,
`render_markdown`, every report value and every localized label are unchanged. The HTML document
stays standalone and email-safe: inline CSS only, no scripts, no external assets, no `url(...)`,
every value escaped once, and the light-only color scheme is preserved.

## Not changed

* MCP stays at **12 tools**, SQLite schema at **version 5**, CLI at **25 top-level commands**.
* No new dependency; no provider call; no change to the write gates or the OAuth flows.
* Report semantics, data limits and `limitations[]` are untouched.

email-text, subject and Markdown tests are unchanged.

The full offline suite is green (2060 passed, 1 skipped), as are `ruff check`,
`ruff format --check`, `mypy src`, the MCP schema drift check and `uv build`. The wheel was
installed into a clean venv: `lv24-seo version` printed `0.15.3`, and `--help`, `export skills`
and the packaged `py.typed`/`store/schema.sql` imports passed.

## Limitations

* Outlook desktop ignores CSS gradients and some border radii; it falls back to the solid dark
  header/footer and square corners. Gmail and Apple Mail render the full styling.
* Email HTML is best-effort by the versioning policy; the JSON envelope and `schemas/tools.json`
  remain the stable surfaces.
* TLS facts describe the connection that served the page; a certificate that changes after the
  body is read is outside this fix.
