# 0.3.0 — honest coverage diffs and week-over-week reports

This release follows a skeptical re-review of 0.2.0. It fixes three honesty bugs, adds proof
tests for the 0.2.0 claims, and ships two read-only features. It is a minor release because it
adds a CLI command and an eleventh MCP tool; no existing input, output field or exit code changed
meaning, except the three bug fixes below.

## Before upgrading

No schema migration. The database from 0.2.0 is used as is; `report diff` reads the existing
`snapshots` table. MCP clients that hard-code the tool list see one new read-only tool,
`seo_report_diff`.

## Fixed (observable changes)

| Area | Before | Now |
|---|---|---|
| Weekly GSC source `meta.total` | a dataset without a provider total was summed as `0`, so "unknown" could surface as a known `0` | `null` unless every dataset reported a total |
| Delivery after a journal COMMIT failure | reported `failed` although the message had already left | `sent` with `reason=delivery_journal_failed` |
| Telegram text over the message limit | cut silently at 4000 characters | cut with an explicit `[truncated: ...]` marker |

## Added

- **Sitemap ↔ crawl coverage diff.** `crawl` and `seo_crawl_site` return
  `data.sitemap_coverage` with six buckets — `unlinked`, `missing_from_sitemap`, `not_ok`,
  `noindex`, `blocked`, `unvisited` — exact `counts`, lists capped at 50, `complete` and
  `limitations[]`. Unvisited sitemap URLs are unknown, never broken; a site without a sitemap gets
  an empty diff labelled "empty, not clean"; a truncated crawl turns `unlinked` and
  `missing_from_sitemap` into candidates.
- **Week-over-week report diff.** `lv24-seo report diff [--base] [--head] [--markdown]` and the MCP
  tool `seo_report_diff` compare two stored weekly snapshots without provider calls: headline
  metrics, issue counts per severity, opportunities added/resolved and limitations added/lifted.
  A metric present in one snapshot only is unknown, not zero; differing period lengths make the
  pair not comparable. The Markdown is deterministic for PR comments and private CI summaries.

## Verified 0.2.0 claims (new tests)

- MCP 2.x runs synchronous handlers in worker threads: a raw sync tool fails to persist (negative
  control); through the async adapter, concurrent `call_tool` requests run serially on the loop
  thread, and `create_server()` / `close_workspaces()` keep data durable.
- Off-origin and robots-disallowed redirect hops, a disallowed seed and off-origin sitemap
  candidates are never requested. `robots.txt` redirects remain followed as RFC 9309 requires.
- Migration 2 marks only GSC daily rows; a failed migration rolls back DDL and the ledger.
- `complete` is `false` for truncated, empty, missing, failed and incomparable sources.

## Operational limits (unchanged)

- The crawler is serial; `crawl.concurrency` is reserved.
- MCP tool calls are serial and block the event loop while the synchronous core runs.
- Limiting is process-local; delivery is at-least-once.
- No paid adapter ships; DataForSEO/SerpApi remain planned BYO-key adapters.
