# 0.4.0 — product email and en/ru/zh localization

This release turns the weekly email from a raw report dump into a product template and makes the
human-readable output configurable in English, Russian and Simplified Chinese. It also fixes
honesty bugs found by a second review: current-only KPIs, invented zero baselines, CTR units and
raw limitation codes.

No database migration is required. JSON snapshots, `report diff`, MCP payloads and machine codes
stay canonical English; the locale is presentation-only.

## Before upgrading

- `report.locale` now accepts `ru | en | zh`. The default remains `ru`, so an installation that
  never set a locale will render human-readable email/CLI/HTML in Russian after upgrading.
- Delivery de-duplication includes the normalized locale for `ru`/`zh`. Switching language
  re-sends the same period once; the English digest is unchanged, so existing English `sends`
  ledger rows still suppress duplicates.
- `only_on_change` and `report.thresholds` still apply: a pure locale switch can be suppressed
  when no material change is present.
- No schema migration; the existing SQLite database and snapshots are used as is.

## Added

- **Product weekly email** for `report weekly --send` and `report weekly --out`:
  - 600px inline-CSS card, dark branded header/footer, hidden preheader, no external images,
    stylesheets, scripts or tracking pixels;
  - hero with property, period and a localized verdict;
  - 2×2 KPI cards for clicks, impressions, CTR and average position, with previous values,
    signed deltas, better/worse wording and a significant badge;
  - top-3 opportunities with localized kind, query, page, one evidence line and estimated clicks;
  - issue severities with counts and unique rule count; critical issues move above opportunities;
  - merged sources with top-query-row labels, Metrica sessions (never clicks), field/lab labels;
  - localized data notes/warnings and a footer with UTC generation time and exact property id.
- **Localized subject, HTML and 78-column plain text** in `en`, `ru`, `zh`; CJK wrapping uses
  display width, Russian uses NBSP grouping and comma decimals, and CTR deltas use percentage
  points (`pp` / `п.п.` / `个百分点`).
- **Current-only KPI rows**: when the current GSC window exists but no comparable previous window
  does, the email shows current values plus "No comparison" instead of "No data".

## Changed

- `report.locale` controls email, Telegram, CLI human summary and `--out` HTML. `--json`,
  `report.json`, MCP payloads and `report diff --markdown` remain canonical English.
- `content_hash` includes the normalized locale for `ru`/`zh`; English keeps the legacy digest.
- Delivery computes the ledger digest per channel from the channel config locale.
- Email layout is responsive (`width:100%;max-width:600px`), with `color-scheme: light only` and
  a CJK font stack.

## Fixed

- No invented `Previous 0`, false `Worse` delta or "stable" verdict when the previous window is
  missing.
- No false "No opportunities found" when only metric totals exist without query/page rows.
- Non-weekly reports no longer show the weekly "No previous period to compare" verdict.
- Raw limitation codes are mapped to localized sentences; unknown codes are labelled
  "Other limitation (code)" instead of leaking `snake_case`.
- Unknown metric rows no longer dump `metric/current/previous/significant/good` into the email.
- Russian severity labels, Chinese source units and the estimate footnote are grammatically
  correct.
- `packages/npm/README.md` documents the localized product email and the email configuration.

## Verified

- Ruff check/format, mypy, gitleaks, actionlint, MCP schema drift and npm launcher tests are green.
- Installed-wheel smoke outside the checkout covers `version`, `--help`, i18n/render imports,
  `export skills`, `py.typed`, `schema.sql` and `Store(':memory:')`.
- No live SMTP send or real email-client pixel QA is part of offline verification.

## Operational limits

- The crawler is serial; `crawl.concurrency` is reserved.
- MCP tool calls are serial and block the event loop while the synchronous core runs.
- Limiting is process-local; delivery is at-least-once.
- Provider prose (unknown limitations/warnings) is shown in its original language with a
  localized label; known codes are translated.
- Non-weekly report bodies remain canonical English; the product template targets the weekly email.
- Sitemap submit / Yandex recrawl return `WRITE_DISABLED`; IndexNow really submits.
