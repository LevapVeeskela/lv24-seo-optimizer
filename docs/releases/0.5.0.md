# 0.5.0 — per-provider stats for the desktop dashboard

This release adds a read-only `stats` command that returns one normalized snapshot across all
six configured SEO services. It exists so the upcoming `lv24-seo-optimizer-desktop` dashboard can
show real metrics, coverage and configuration gaps instead of parsing report prose or inventing
zeros.

No schema migration. Existing CLI commands, JSON envelopes and stored snapshots are unchanged.

## Added

`lv24-seo stats --days 7 --lag-days 2 --json` returns the standard envelope with:

- `period` and `previous_period`;
- `services[]` in stable order: GSC, Yandex Webmaster, Yandex Metrika, Bing, CrUX, PSI;
- per service: `provider`, `label`, `configured`, `ready`, `status`, `metrics`, `previous`,
  `rows`, `data_age_days`, `truncated`, `limitations`, `warnings`, `error`;
- `coverage`: configured/returned/failed/missing/complete;
- aggregate `limitations` and `warnings`;
- `meta`: period, previous period, days, lag days, complete, truncated, data age.

Statuses: `ok`, `no_data`, `missing_token`, `not_configured`, `error`. A failing provider is
isolated; the overall command still returns `ok: true` with that service's error.

Metrics by provider:

| Provider | Metrics | Previous |
|---|---|---|
| GSC | clicks, impressions, ctr (0..1), position | yes |
| Yandex Webmaster | shows, clicks, position | yes |
| Yandex Metrika | visits, users | yes |
| Bing | clicks, impressions, position | null (API has no window) |
| CrUX | metric -> p75, plus units (ms/score) | null |
| PSI | performance/seo scores (0..1), field p75s | null |

CrUX field data is p75. PSI is lab data from the first configured URL; it is never averaged across
URLs, and multiple URLs add an explicit limitation. `rows` is the number of rows returned, not a
provider total.

## Behavior

- `stats` is read-only: it never creates snapshots, pages or issues and does not require a Store.
- No cross-engine totals: GSC, Yandex, Bing and Metrika measure different things.
- Missing values stay missing; the command does not zero-fill an unavailable CTR or position.
- `coverage.complete` is true only when every configured service returned `ok`, has rows, is not
  truncated, and no configured service is missing or failed.

## Verified

- Offline suite: 1092 passed, 1 skipped.
- `ruff check`, `ruff format --check`, `mypy src` clean.
- `stats` has 17 offline fake-client tests covering all providers, missing tokens, no data,
  provider errors, PSI multi-URL limits, read-only behavior and CLI output.

## Limits

- Provider prose in `limitations`/`warnings` remains provider-authored text.
- PSI shows the first configured URL's metrics; rows cover up to five URLs.
- `stats` is a point-in-time dashboard, not a historical series; use stored weekly snapshots for
  history and diff.
