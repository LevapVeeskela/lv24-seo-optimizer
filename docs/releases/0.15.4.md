# 0.15.4 - Configurable title threshold and the documented CSP exception

Status: **released** (2026-11-20) on PyPI, npm and the MCP Registry. Desktop `0.9.9` bundles
engine `0.15.3`.

Patch release: two crawl-rule options. Both keep the previous findings by default, so an existing
`seo.toml` and every stored report behave exactly as before.

## Added

### `crawl.title_max_length`

The `title-length` rule hard-coded 60 characters. Sites whose CMS template intentionally produces
61-70 character titles had to accept a finding they could not fix.

`crawl.title_max_length` (default `60`, minimum `15`) is now the upper bound; `15` remains the
lower bound. Config validation rejects a value below 15 (`CONFIG_INVALID`), so the rule can never
report everything as too short. `title-missing` and every other rule are unaffected.

### `crawl.csp_allow_style_attr_inline`

The `security-headers` rule reports any `unsafe-inline` or `unsafe-eval` in
`Content-Security-Policy`. A single-page app that renders map popups and markers with literal
`style` attributes cannot nonce those attributes and legitimately needs
`style-src-attr 'unsafe-inline'`.

`crawl.csp_allow_style_attr_inline = true` tolerates exactly that form. `style-src`,
`style-src-elem`, `script-src`, `default-src`, `unsafe-eval` and every other unsafe token are still
reported, so the exception cannot be used to silence a weak policy. Default: `false`. Enable it
only when `style-src` itself is strict; otherwise the finding is real, not noise.

## Fixed

### CSP directives are parsed, not substring-matched

The old check searched the raw header for each unsafe token. It now parses the policy into
directive/source pairs, which the opt-in exception requires. Repeated directive names are merged
instead of overwritten, so an unsafe token in a duplicated directive can no longer hide from the
finding. Reported fields (`header`, `status`, `unsafe`) and severity are unchanged.

## Not changed

* MCP stays at **12 tools**, SQLite schema at **version 5**, CLI at **25 top-level commands**.
* No new dependency; no provider call; no change to the write gates, OAuth flows or the JSON
  envelope.
* Defaults reproduce the previous results: 60-character titles and every `unsafe-inline` or
  `unsafe-eval` are still reported.

Unit tests cover the config bounds, the rule reading `title_max_length` (including the 15 lower

the guarantee that `style-src`, `script-src` and `unsafe-eval` stay reportable while the exception

The full offline suite is green (2068 passed, 1 skipped), as are `ruff check`,
`ruff format --check`, `mypy src`, the MCP schema drift check and `uv build`. The wheel was
installed into a clean venv: `lv24-seo version` printed `0.15.4`, and `--help`, `export skills`
(3 skills) and the packaged `py.typed`/`store/schema.sql` imports passed.

## Limitations

* `csp_allow_style_attr_inline` is a narrow, per-project opt-in. It does not relax CSP checks for
  other directives, and it cannot detect a `style-src-attr` value built from a nonce or hash.
* `title_max_length` applies to the `title-length` rule only; `title-missing` and other content
  rules have their own limits.
* Crawl findings remain best-effort samples of the crawled URL set, not a full-site guarantee.
