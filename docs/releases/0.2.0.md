# 0.2.0 — correctness and safety review

This release applies the technical-audit corrections and a second review of the
implementation. It changes reported numbers and findings by removing invalid
comparisons, unknown-as-zero assumptions and unvisited-as-broken classifications.

## Before upgrading

Back up the configured SQLite database. Migrations preserve historical rows;
rows whose daily/window granularity cannot be recovered are labelled
`legacy_unknown_granularity` and excluded from normal daily reads. Explicit
repository access with `include_legacy=True` remains available.

The weekly headline compares GSC windows only. Other providers keep separate
sections. A missing/capped/sampled input or missing comparison prevents a
complete-data claim. GSC query coverage is bounded by the API even below the
caller row cap; absent queries are not automatically zero traffic.

F19's URL-identity issue is fixed. Bounded parallel crawling is not implemented:
`crawl.concurrency` is reserved and the crawler runs serially with pacing.

## Operational limits

- Limiting is process-local, not a durable account-wide daily quota.
- Delivery is at-least-once after a crash or ambiguous remote acceptance.
- Windows task XML stores an offset, not an IANA zone's future seasonal rules.
- Injected transports are trusted embedding/test boundaries; the default
  crawler transport applies the address policy.
- No raw provider archives, service-account/refresh auth flow or live property
  acceptance test is included. Sitemap submit and Yandex recrawl remain disabled.
- Live API calls, real email/Telegram sends and task installation are not part
  of offline verification.
